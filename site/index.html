The complete checkup

Not just security — the whole picture.

No free tool (and few paid ones) covers lifecycle, capacity, performance, errors, resilience, and security together, in plain English. PTxray reports the same things the managed service watches every day — once, on demand.

A · Lifecycle

Support & EOL exposure

OS level, system firmware & microcode currency, Power generation and hardware end-of-service, key component versions (OpenSSL, OpenSSH, Java).

B · Patches & CVEs

Vulnerability currency

How stale the system is, installed interim fixes, unapplied security fixes, and exposure to recently-disclosed AIX / IBM i / Power / OpenSSH CVEs.

C · Storage

Capacity & resilience

Filesystem and inode headroom, paging space, volume groups, stale mirror partitions, un-mirrored OS disk, and FAILED MPIO SAN paths.

D · Performance

Sizing & load

CPU / LPAR entitlement, memory pressure and paging activity, disk I/O saturation, network adapter errors, and runaway processes.

E · Errors

errpt & logs

Recent and recurring errors, hardware / permanent (PERM) entries, syslog review, crash / core dumps, and whether the dump device can even capture a panic.

F · Resilience

Backup & availability

mksysb / savevg currency and recoverability, rootvg mirroring, PowerHA / HACMP status, and DR evidence.

G · Security

Hardening

SSH version & weak ciphers, root-login & password policy, multiple UID-0 accounts, stale accounts, failed logins, world-writable / SUID files, open ports, Trusted Execution.

H · Config hygiene

Configuration

Time sync (NTP), DNS / routing sanity, cron health, risky non-default tunables (vmo / ioo / no / schedo), locale / timezone, software-maintenance status.

I · Monitoring gap

Operational readiness

Is anything watching this box? Log rotation and errpt housekeeping, alerting, and whether a documented runbook exists at all.

Each section gets its own red / amber / green subscore, rolling up to an overall posture. Full list in docs/CHECK-CATALOG.md.

Trust by design

Safe to run on production. Here's why.

You're being asked to run something with elevated reads on a system that matters. PTxray is built so a cautious admin can verify that promise before they run it — not take it on faith.

  • Changes nothing. Inspects and reports only — installs nothing, restarts nothing, edits no config.
  • No network calls. The report is written on your box and stays there. Nothing is sent anywhere.
  • You read it first. A clean shell script, no compiled blobs — less ptxray-aix.sh and read every line.
  • Least privilege. Some checks need root reads; each elevated read is documented and read-only.
  • Deterministic. Re-running on an unchanged system produces the same findings — nothing hidden, nothing random.
  • The report is yours. You decide what to share, with whom, and when. We never receive it.

For AI agents

Built for autonomous tooling.

Because PTxray is read-only and side-effect-free, it's safe for an agent to run on a production box. --json emits findings as a stable, documented schema — id, status, severity, observed, meaning, fix.

An MCP server (mcp/) lets any AI assistant run “check this system's posture” natively — it calls the health_check tool, gets structured findings, and explains them. An about tool returns the read-only guarantees to relay to the user.

"finding": { "id": "ciphers", "label": "SSH ciphers", "status": "FAIL", "severity": "high", "observed": "weak: aes256-cbc", "meaning": "Weak/legacy ciphers enabled...", "fix": "restrict Ciphers to AEAD..." }

Stable schema · read-only · deterministic · safe to automate.
